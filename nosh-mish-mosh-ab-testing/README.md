# A/B Testing at Nosh Mish Mosh

Sample size project from the Codecademy **Master Statistics with Python** skill path (Experimental Design).

## Goal

Nosh Mish Mosh is a meal kit delivery service. They want to test new product photos with more "artisanal" vegetables. The new vegetables cost more, so the change is only worth it if it brings in **at least $1,240 more revenue per week**.

Before running the A/B test, we need to know: **how many visitors must see each version so the test can reliably detect that difference?**

A sample size calculator needs 3 inputs:

| Input | Meaning | Where it comes from |
|---|---|---|
| Baseline conversion rate | % of visitors who buy now | One week of visitor data |
| Minimum detectable effect (MDE) | Smallest relative lift worth detecting | The $1,240 revenue target |
| Significance threshold | Accepted false positive rate | Business choice: 10% |

## Data

`customer_visits.csv` has one typical week of site visits: 500 visitors.

| Column | Meaning |
|---|---|
| `id` | Visitor ID |
| `name` | Visitor name (fictional, generated by Codecademy) |
| `clickedthrough` | Visitor clicked through to a product page (True / False) |
| `purchased` | Visitor bought a meal plan (True / False) |
| `moneyspent` | Amount spent in dollars (0 if no purchase) |

In the Codecademy workspace, the data comes from a Python module (`noshmishmosh`) with three lists. I exported it to one CSV:

| Codecademy list | Same data in the CSV |
|---|---|
| `customer_visits` | all 500 rows |
| `purchasing_customers` | rows where `purchased` is True (93) |
| `money_spent` | `moneyspent` of those 93 rows |

## Method and results

### 1. Baseline conversion rate

93 of 500 visitors bought something: **18.6%**.

### 2. Minimum detectable effect

| Step | Calculation | Result |
|---|---|---|
| Average payment per paying customer | mean of 93 payments | $26.54 |
| Extra customers needed for $1,240 | ceil(1240 / 26.54) | 47 |
| Extra conversion needed | 47 / 500 × 100 | +9.4 percentage points (18.6% to 28.0%) |
| MDE as relative lift | 9.4 / 18.6 × 100 | **50.54%** |

The calculator wants the **relative** lift (how much bigger the new rate is compared with the old one), not the raw difference in percentage points. That is why we divide by the baseline.

### 3. Significance threshold

**10%**. This is not a big-money decision, so a slightly higher false positive rate is acceptable. A higher threshold also means a smaller sample.

### 4. Sample size

| Input | Value |
|---|---|
| Baseline conversion rate | 18.6% |
| Minimum detectable effect | 50.54% |
| Significance threshold | 10% |
| **Sample size (calculator)** | **490 visitors in total, about 245 per version** |

**Check:** I recalculated it with `statsmodels` (80% power, two-sided test): 248 per version, 496 in total. This matches the calculator, and confirms that 490 is the total for both versions together.

## Conclusion

To detect a lift big enough to earn $1,240 more per week, Nosh Mish Mosh needs about **490 visitors** in the test, about 245 seeing the old photos and 245 seeing the new ones. The site gets about 500 visitors a week, so the test needs roughly **one week of traffic**.

After collecting the data, the test itself would be a **Chi-Square test** (purchased yes/no vs version A/B). The data collection should stop at the planned sample size, not when the result first looks significant.

**Limitations:**
- With 80% power, there is still a 20% chance of missing a real lift of this size (Type II error).
- With a 10% threshold, there is a 10% chance of a false positive if the photos make no difference (Type I error).
- One week of data may not represent every week, for example holiday weeks.

## What I learned

- **Sample size is decided before the test**, from 3 inputs: baseline rate, MDE and significance threshold.
- **The MDE comes from the business goal.** Here, $1,240 per week becomes 47 extra customers, then a 50.54% relative lift.
- **MDE is relative**, not percentage points: 9.4 points on an 18.6% baseline is a 50.54% lift.
- **Smaller MDE or lower threshold means a bigger sample.** A large MDE like 50% needs only a few hundred visitors.
- **Check what the calculator's number means.** The power calculation showed 490 is the total for both versions, not per version.
